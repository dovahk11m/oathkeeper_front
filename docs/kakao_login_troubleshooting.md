# 카카오 로그인 연동 문제 해결 과정 요약

이 문서는 카카오 소셜 로그인을 연동하며 겪었던 문제들과 해결 과정을 정리한 문서입니다.

---

## 1단계: 최초 시도와 실패

### 문제
- 구글 로그인 등 다른 표준 OAuth 2.0 경험을 바탕으로, 카카오 개발자 센터에서 발급받은 API 키만 사용하여 서버와 클라이언트(앱)에 로그인 코드를 작성했습니다.

### 결과
- 전혀 동작하지 않았습니다. 표준 OAuth 2.0 흐름과 카카오의 구현 방식에 차이가 있음을 확인했습니다.

---

## 2단계: 카카오의 고유 요구사항 파악

### 문제
- 카카오 로그인이 정상 동작하려면 단순 API 키 외에 **키 해시(Key Hash)**와 **리다이렉트 URI(Redirect URI)**를 정확히 설정해야 한다는 사실을 파악했습니다.
- 개발 환경(디버그)과 프로덕션 환경(릴리즈)의 키 해시는 서로 다릅니다.
- 안드로이드 플랫폼 설정에 이 값들을 등록해야 했습니다.

### 조치
- `keytool` 또는 `MainActivity.kt`에 임시 코드를 추가하는 방식으로 디버그 키 해시를 추출했습니다.
- 추출한 키 해시와 앱 패키지에 맞는 리다이렉트 URI(`kakao{NATIVE_APP_KEY}://oauth`)를 카카오 개발자 센터, 서버, 클라이언트에 모두 설정했습니다.

### 결과
- 여전히 로그인이 성공하지 않았습니다. 클라이언트 설정 외에 다른 문제가 있음을 인지했습니다.

---

## 3단계: 서버-클라이언트 통신 방식 재정비

### 문제
- 클라이언트(앱)는 카카오 SDK로부터 **액세스 토큰(Access Token)**을 받아옵니다.
- 이 토큰을 우리 앱 서버로 보내면, 서버는 이 토큰을 이용해 카카오 API 서버에 다시 사용자 정보를 요청하고 검증합니다.
- 이 과정에서 서버의 API 명세(`API_AUTH.md`)와 클라이언트가 보내는 요청 데이터 형식이 일치하지 않았습니다. (예: `code` vs `access_token` 필드명 불일치)

### 조치
- 클라이언트가 카카오 SDK로부터 받은 `Access Token`을 `{ "access_token": "..." }` 형식으로 서버에 보내도록 `LoginStrategy`와 관련 DTO를 수정했습니다.
- 서버 또한 이 요청을 받아 처리하도록 API 로직을 전면 재검토하고 수정했습니다.

### 결과
- 서버와의 통신 규격이 통일되었고, 서버는 카카오로부터 사용자 정보를 받아오는 데 성공했습니다.

---

## 4단계: 사용자 정보 처리 (이메일 누락)

### 문제
- 카카오 정책상 사용자가 이메일 제공에 동의하지 않거나, 계정에 이메일이 없는 경우가 있습니다.
- 우리 서비스는 이메일을 회원 식별의 주요 수단으로 사용하고 있어, 이메일이 `null`로 들어오면 회원가입/로그인 로직에서 오류가 발생했습니다.

### 조치
- 서버 로직을 수정하여, 카카오로부터 이메일을 받지 못한 경우 `kakao_{회원번호}@social.com` 과 같은 **가상(dummy) 이메일 주소**를 생성하여 회원 DB에 저장하도록 했습니다.

### 결과
- **실제 기기(Real Device)에서 처음으로 로그인에 성공했습니다!**

---

## 5단계: 가상 머신(AVD) 테스트 실패와 해결

### 문제
- 실제 기기에서는 성공했지만, 카카오톡 앱이 설치되지 않은 안드로이드 가상 머신(AVD)에서는 로그인 버튼을 눌러도 무한 로딩에 빠지는 현상이 발생했습니다.

### 원인
- 카카오톡 앱이 없는 환경에서는 **웹뷰(WebView)**를 통해 카카오 계정 로그인을 진행합니다.
- 로그인 성공 후 웹뷰는 설정된 리다이렉트 URI로 돌아오려 하지만, 이를 처리할 `Activity`가 `AndroidManifest.xml`에 등록되어 있지 않았습니다.
- 기존 `<intent-filter>`는 `MainActivity`에 설정되어 있었으나, 이는 카카오톡 앱을 통한 인증에만 사용되며 웹뷰 로그인 콜백은 처리하지 못합니다.

### 조치
- `AndroidManifest.xml` 파일을 수정하여, 카카오 SDK가 제공하는 `AuthCodeCustomTabsActivity`를 등록했습니다.
- 이 `Activity`에 웹뷰 로그인 콜백을 받기 위한 `<intent-filter>`와 리다이렉트 URI(`data` 태그)를 명시적으로 설정해주었습니다.
- 역할이 중복되지 않도록 `MainActivity`에 있던 기존 콜백용 `<intent-filter>`는 제거하여 코드를 명확히 정리했습니다.

### 결과
- **가상 머신에서도 웹뷰를 통한 카카오 로그인이 정상적으로 동작하는 것을 확인했습니다.** 이로써 모든 로그인 시나리오에 대한 대응을 완료했습니다.

---

## 최종 로그인 흐름 정리

### 상세 설명

현재 우리 앱의 카카오 로그인 로직은 **클라이언트(앱)**, **우리 서버**, **카카오 서버** 세 주체가 상호작용하는 구조입니다.

1.  **클라이언트 → 카카오 서버 (인증 및 토큰 발급)**
    *   **사용자 행동**: 사용자가 "카카오로 시작하기" 버튼을 누릅니다.
    *   **앱 (AuthNotifier)**: `signInWithKakao()` 메소드가 호출됩니다.
    *   **앱 (KakaoLoginAdapter)**: 카카오톡 앱 설치 여부를 확인합니다.
        *   **앱 설치 O**: 카카오톡 앱을 실행시켜 사용자에게 인증을 요청합니다.
        *   **앱 설치 X**: 웹뷰(Chrome Custom Tabs)를 열어 카카오 계정 로그인 페이지를 보여줍니다.
    *   **카카오 서버**: 사용자가 인증(로그인, 동의)을 완료하면, 카카오 서버는 앱으로 **액세스 토큰(Access Token)**을 발급해 줍니다. 이 토큰은 "방금 그 사용자가 카카오 로그인을 성공했다"는 일회성 증표입니다.

2.  **클라이언트 → 우리 서버 (로그인/회원가입 요청)**
    *   **앱 (AuthNotifier)**: 카카오로부터 받은 액세스 토큰을 `KakaoLoginStrategy`에 담아 `login()` 메소드를 호출합니다.
    *   **앱 (KakaoLoginStrategy)**: `dio`를 이용해 우리 서버의 API(`POST /api/member/kakao/token`)로 액세스 토큰을 전송합니다.

3.  **우리 서버 ⇔ 카카오 서버 (사용자 검증)**
    *   **우리 서버**: 앱으로부터 받은 액세스 토큰이 진짜인지 확인하기 위해, 해당 토큰을 카카오 서버 API로 보내 사용자 정보를 요청합니다.
    *   **카카오 서버**: 토큰이 유효하면 해당 사용자의 정보(닉네임, 이메일 등)를 우리 서버로 보내줍니다.

4.  **우리 서버 → 클라이언트 (최종 로그인 처리)**
    *   **우리 서버**: 카카오로부터 받은 사용자 정보를 바탕으로 우리 서비스의 DB를 확인합니다.
        *   **기존 회원**: 바로 로그인 처리를 합니다.
        *   **신규 회원**: 회원가입을 시킵니다. (이때 이메일이 없으면 더미 이메일을 생성합니다)
    *   **우리 서버**: 로그인/회원가입이 완료되면, 우리 서비스 전용 **JWT 토큰**과 회원 정보를 생성하여 클라이언트(앱)에 최종 응답을 보냅니다.
    *   **앱 (AuthNotifier)**: 서버로부터 받은 JWT 토큰과 회원 정보를 `AuthState`에 저장합니다.
    *   **앱 (UI)**: `AuthState`의 변경을 감지하고, 로그인된 사용자가 있으므로 홈 화면으로 자동 전환합니다.

   |
   V

   |                                                                                               |

   |                                                                                               |
   V                                                                                               |

   |                                                                                               |

   |                                                                                               |

   |                                                                                               |

   |
   V

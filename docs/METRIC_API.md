# Metrics & AI 요약 API 명세

- **최종 수정일:** 2025-11-25
- **작성자:** Oath 서버 개발팀

이 문서는 클라이언트 개발자가 Oath 서비스의 **AI 요약 기능**을 연동하는 데 필요한 모든 API 정보를 제공합니다. 약속(Plan) 단위의 개별 요약과 그룹(Group) 단위의 누적 요약 기능을 모두 포함합니다.

---

## ※ 클라이언트 개발자 필독 가이드: 폴링(Polling) 방식 ※

**AI 요약 기능의 핵심은 '비동기 폴링(Asynchronous Polling)' 방식으로 동작한다는 것입니다.** AI 서버가 요약을 생성하는 데 시간이 걸리기 때문에, 클라이언트는 아래와 같은 흐름으로 API를 호출해야 합니다.

1.  **최초 요청:** 클라이언트는 요약이 필요한 시점(예: 화면 진입)에 요약 API(`.../summary`)를 **최초 호출**합니다.
2.  **상태 확인:** 서버는 즉시 결과를 반환하는 대신, 요약의 현재 상태를 알려줍니다.
    - **`202 Accepted` 응답 (상태: `PENDING`):** 요약이 아직 생성 중이라는 의미입니다. 클라이언트는 **3~5초 간격으로 동일한 API를 다시 호출**해야 합니다. (이때 사용자에게 로딩 인디케이터를 보여주는 것이 좋습니다.)
    - **`200 OK` 응답 (상태: `COMPLETED` 또는 `FAILED`):** 요약 생성이 완료되었거나 실패했다는 의미입니다. 클라이언트는 응답받은 `data`를 화면에 표시하고, **폴링을 중단**합니다.
3.  **타임아웃 처리:** 약 30초 이상 폴링을 계속해도 `PENDING` 상태가 유지된다면, 네트워크 문제나 서버 오류일 수 있으므로 "시간이 너무 오래 걸립니다. 다시 시도해주세요."와 같은 메시지를 표시하고 폴링을 중단하는 것을 권장합니다.

**이 폴링 방식은 아래에 설명된 '1. 약속(Plan) 단위 요약'과 '2. 그룹(Group) 단위 요약' API 모두에 동일하게 적용됩니다.**

---

## 1. 약속(Plan) 단위 요약

### `GET /api/plans/{planId}/summary`

- **설명:** 특정 약속(`planId`) 하나에 대한 AI 요약 보고서를 요청합니다.
- **인증:** 필요 (JWT 토큰)
- **동작 방식:** 이 API는 요약 생성에 시간이 걸릴 수 있어 **폴링(Polling)** 방식으로 동작합니다.

#### 1.1. 응답 시나리오

**1) 요약 생성 시작 또는 진행 중일 때**

- **HTTP Status:** `202 Accepted`
- **응답 본문:**
  ```json
  {
    "success": true,
    "data": { "summaryStatus": "PENDING", ... },
    "message": "AI 요약 보고서가 생성 중입니다. 잠시 후 다시 시도해주세요."
  }
  ```
- **클라이언트 처리:** 이 응답을 받으면, **3~5초 간격으로 동일한 API를 다시 호출**해야 합니다.

**2) 요약 생성 완료 시**

- **HTTP Status:** `200 OK`
- **응답 본문:**
  ```json
  {
    "success": true,
    "data": {
      "summaryStatus": "COMPLETED",
      "summary": "약속 #2의 요약입니다. 총 16건의 기록이 있으며...",
      ...
    },
    "message": "그룹 통계 조회가 완료되었습니다."
  }
  ```
- **클라이언트 처리:** `data.summary`를 화면에 표시하고, 폴링을 중단합니다.

**3) 요약 생성 실패 시**

- **HTTP Status:** `200 OK` (또는 500 Internal Server Error)
- **응답 본문:**
  ```json
  {
    "success": true,
    "data": { "summaryStatus": "FAILED", "summary": "AI 요약 생성에 실패했습니다.", ... },
    "message": "그룹 통계 조회가 완료되었습니다."
  }
  ```
- **클라이언트 처리:** 사용자에게 오류 메시지를 표시하고, 폴링을 중단합니다.

## 2. 그룹(Group) 요약 기능

그룹 요약 화면은 크게 '그룹 전체의 누적 통계'를 보여주는 기능과 '그룹에 속한 개별 약속 목록'을 보여주는 기능으로 구성됩니다. 이 두 기능을 구현하기 위해 아래 API들을 사용합니다.

### 2.1. 그룹 누적 통계 조회

- **URL**: `GET /api/groups/{groupId}/metrics/summary`
- **설명:** 특정 그룹(`groupId`)의 누적 통계와 AI 요약을 조회합니다.
- **인증:** 필요 (JWT 토큰)
- **동작 방식:** 개별 약속 요약과 마찬가지로 **폴링(Polling)** 방식으로 동작합니다. 최초 호출 시 요약 생성을 요청할 수 있습니다.

#### 응답 시나리오

**1) 요약 생성 시작 또는 진행 중일 때**

- **HTTP Status:** `202 Accepted`
- **응답 본문:**
  ```json
  {
    "success": true,
    "data": {
      "groupId": 1,
      "summaryStatus": "PENDING",
      "summary": "AI 요약 보고서가 생성 중입니다.",
      ...
    },
    "message": "그룹 요약이 생성 중입니다. 잠시 후 다시 시도해주세요."
  }
  ```
- **클라이언트 처리:** 이 응답을 받으면, **3~5초 간격으로 동일한 API를 다시 호출**해야 합니다.

**2) 요약 생성 완료 시**

- **HTTP Status:** `200 OK`
- **응답 본문:**
  ```json
  {
    "success": true,
    "data": {
      "groupId": 1,
      "summaryStatus": "COMPLETED",
      "summary": "분석된 4개의 약속에 따르면, 이 그룹은 약속당 평균 64.6km를 이동했으며...",
      "summaryLastUpdatedAt": "2025-11-25T18:00:00",
      "totalPlansCompleted": 4,
      ...
    },
    "message": "그룹 통계 조회가 완료되었습니다."
  }
  ```
- **클라이언트 처리:** `data` 객체의 정보를 화면에 표시하고, 폴링을 중단합니다.

**3) 요약 생성 실패 시**

- **HTTP Status:** `200 OK`
- **응답 본문:**
  ```json
  {
    "success": true,
    "data": {
      "groupId": 1,
      "summaryStatus": "FAILED",
      "summary": "AI 요약 생성에 실패했습니다.",
      ...
    },
    "message": "그룹 통계 조회가 완료되었습니다."
  }
  ```
- **클라이언트 처리:** 사용자에게 오류 메시지를 표시하고, 폴링을 중단합니다.

### 2.2. 그룹 내 약속 목록 조회

- **URL**: `GET /api/groups/{groupId}/plans`
- **설명**: 특정 그룹에 속한 약속 목록을 페이징하여 조회합니다. 그룹 요약 화면의 '약속 목록' 탭을 구현하는 데 사용됩니다.
- **인증**: 필요 (JWT 토큰)
- **Success Response (200 OK)**:
  ```json
  {
    "success": true,
    "data": {
      "content": [ { "planId": 2, "title": "긴급 트러블슈팅 회의", ... } ], ...
    },
    "message": "그룹 내 약속 목록 조회가 완료되었습니다."
  }
  ```
- **클라이언트 구현 가이드**: 이 API로 약속 목록을 가져온 후, 사용자가 특정 약속을 선택하면 **1. 약속(Plan) 단위 요약** API를 호출하여 상세 요약을 보여줄 수 있습니다.

## 3. 참고: 내부 테스트용 API

> **[주의]** 아래 API들은 서버 개발팀이 `local` 프로필에서만 사용하는 테스트용 API입니다. 클라이언트에서는 **절대 직접 호출하면 안 됩니다.** 모든 API의 기본 경로는 `/api/test/metrics/plans/{planId}` 입니다.

- **`POST /refresh`**: [전체 파이프라인 실행] 통계 계산부터 AI 서버 연동까지 순차적으로 실행합니다.
- **`POST /rollup`**: [1단계] 약속 전체 통계를 수동으로 계산(Rollup)합니다.
- **`POST /participants/{participantId}/rollup`**: [1.1단계] 특정 참가자의 통계만 다시 계산합니다.
- **`GET`**: [2단계] 계산된 약속별 멤버 통계를 DB에서 직접 조회합니다.
- **`POST /push`**: [3단계] 계산된 통계를 AI 서버로 수동 전송(Push)합니다.
- **`GET /summary`**: [4단계] AI 서버의 JSON 요약에 DB의 '회원 이름'을 주입하여 조회합니다.
- **`POST /summary/text`**: [4.1단계] LLM 옵션을 포함하여 텍스트 요약을 생성/조회합니다.

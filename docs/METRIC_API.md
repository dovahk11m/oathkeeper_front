# Metrics & AI 요약 API 명세

- **최종 수정 일자:** 2025-11-26 (업데이트)
- **작성자:** Oath 서버 개발팀

이 문서는 클라이언트(Flutter) 개발자가 그룹(Group)에 대한 AI 요약 보고서를 조회하는 방법에 대해 안내합니다.

---

## 1. 핵심 API: AI 그룹 요약 보고서 조회

AI 그룹 요약 보고서는 생성에 시간이 소요되는 **비동기 작업**입니다. 따라서 클라이언트는 아래 API를 **주기적으로 호출(Polling)**하여 최종 결과물을 받아야 합니다.

### `GET /api/groups/{groupId}/metrics/summary`

- **설명:** 특정 그룹(`groupId`)에 대한 AI 요약 보고서를 요청하고, 진행 상태를 조회합니다.
- **인증:** 필요 (JWT 토큰)

#### 1.1. 응답 시나리오

이 API는 요약 진행 상태(`SummaryStatus`)에 따라 세 가지 다른 응답을 반환합니다.

**1) 요약 생성 시작 또는 진행 중일 때**

- **조건:** 서버가 요약 생성을 막 시작했거나, 아직 처리 중인 경우.
- **HTTP Status:** `200 OK`
- **응답 본문:**
  ```json
  {
    "success": true,
    "data": {
      "groupId": 1,
      "summary": null,
      "status": "PENDING",
      "lastUpdatedAt": "2025-11-26T10:00:00",
      "reason": "그룹 요약 정보 생성 중입니다. 잠시 후 다시 시도해주세요."
    },
    "message": "그룹 요약 정보 생성 중입니다."
  }
  ```
- **클라이언트 처리 (Flutter 예시):**
  - 이 응답을 받으면, **2~3초 간격으로 동일한 API를 다시 호출**해야 합니다.
  - `CircularProgressIndicator`와 같은 로딩 인디케이터를 사용자에게 표시하는 것이 좋습니다.
  - `data.reason` 필드를 로딩 상태 메시지로 보여줄 수 있습니다.

**2) 요약 생성 완료 시**

- **조건:** AI 요약 보고서 생성이 성공적으로 완료된 경우.
- **HTTP Status:** `200 OK`
- **응답 본문:**
  ```json
  {
    "success": true,
    "data": {
      "groupId": 1,
      "summary": "분석된 4개의 약속에 따르면, 이 그룹은 약속당 평균 64.6km를 이동했으며, 평균 11.25분의 지각 시간을 기록했습니다. 전반적으로 장거리 이동이 잦고, 약속 시간을 준수하는 데 약간의 어려움이 있는 경향을 보입니다.",
      "status": "COMPLETED",
      "lastUpdatedAt": "2025-11-26T10:05:00",
      "reason": null
    },
    "message": "그룹 요약 정보가 성공적으로 조회되었습니다."
  }
  ```
- **클라이언트 처리 (Flutter 예시):**
  - `data.summary`에 포함된 텍스트를 `Text` 위젯 등을 사용하여 화면에 표시합니다.
  - 이 응답을 받으면 폴링을 중단합니다.
  - `lastUpdatedAt` 정보를 사용자에게 보여주어 요약 정보의 최신성을 알릴 수 있습니다.

**3) 요약 생성 실패 시**

- **조건:** AI 서버 통신 오류, 데이터 부족 등 예측 가능한 문제로 요약 생성에 실패한 경우.
- **HTTP Status:** `200 OK` (서버가 실패를 인지하고 정상적으로 응답)
- **응답 본문:**
  ```json
  {
    "success": true,
    "data": {
      "groupId": 1,
      "summary": null,
      "status": "FAILED",
      "lastUpdatedAt": "2025-11-26T10:05:00",
      "reason": "AI 요약 생성에 실패했습니다: 분석할 데이터가 부족합니다."
    },
    "message": "AI 요약 생성에 실패했습니다."
  }
  ```
- **클라이언트 처리 (Flutter 예시):**
  - 사용자에게 `data.reason` 필드의 실패 사유를 명확히 보여주고, "다시 시도" 버튼을 제공하는 것을 권장합니다.
  - 폴링을 중단합니다.

#### 1.2. 실패 응답: `200 OK` vs `500 Internal Server Error`

클라이언트는 실패 상황을 아래 두 가지 기준으로 처리해야 합니다.

-   **`200 OK` + `status: "FAILED"` (예측된 실패):**
    -   **언제 발생?** AI 서버 통신 오류, AI 모델 타임아웃, 분석할 데이터 부족 등 서버가 **실패를 인지하고 제어할 수 있는** 대부분의 경우에 해당합니다.
    -   **클라이언트 처리:** `data.reason`에 담긴 실패 사유를 사용자에게 안내하고, 재시도 로직을 구현합니다.

-   **`500 Internal Server Error` (예측하지 못한 실패):**
    -   **언제 발생?** 데이터베이스 연결 불가 등 서버의 핵심 기능이 마비되어 **정상적인 JSON 응답조차 만들어낼 수 없는** 매우 드문 예외 상황입니다.
    -   **클라이언트 처리:** 일반적인 '서버 접속 오류'로 간주하고, "서버에 문제가 발생했습니다. 잠시 후 다시 시도해주세요." 와 같은 공통 오류 메시지를 표시합니다.

#### 1.3. 전체 흐름 요약 (Polling)

1.  클라이언트는 그룹 상세 화면에 진입 시 `GET /api/groups/{groupId}/metrics/summary`를 **최초 호출**합니다.
2.  응답 `data.status` 필드가 `PENDING`인 경우, 2~3초 대기 후 **다시 호출**합니다.
3.  `data.status` 필드가 `FAILED`인 경우, `data.reason`을 사용자에게 보여주고 **호출을 중단**합니다. (재시도 옵션 제공 권장)
4.  `data.status` 필드가 `COMPLETED`인 경우, `data.summary`를 화면에 표시하고 **호출을 중단**합니다.

## 2. 참고: 내부 테스트용 API

> **[주의]** 아래 API들은 서버 개발팀이 로컬 환경에서 테스트 목적으로만 사용하는 API입니다. 클라이언트에서는 **절대 직접 호출하면 안 됩니다.**

- **`POST /api/plans/{planId}/metrics/rollup`**: 수동으로 통계 계산을 트리거합니다.
- **`POST /api/plans/{planId}/metrics/push`**: 계산된 통계를 AI 서버로 수동 전송합니다.

이 API들은 실제 서비스 환경에서는 비활성화되어 있습니다.

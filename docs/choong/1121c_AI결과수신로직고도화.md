## 상황 설명

AI가 생성하는 '약속 요약 보고서'는 처리 시간이 길어 동기 API 호출 시 타임아웃이 발생할 수 있음. 이 문제를 해결하고 안정적인 서비스를 제공하기 위해, 비동기 폴링(Polling) 아키텍처를 도입하기로 결정함.

- **주요 목표:** AI 서버 연동 기능의 전체 파이프라인을 완성하고, 안정성을 높여 운영 가능한 수준으로 고도화함.

## 1. 오전: AI 요약 보고서 제공 API 구현 (기본 파이프라인 구축)

AI 서버와 연동하여 특정 약속(Plan)에 대한 요약 정보를 제공하는 API(`GET /api/plans/{planId}/summary`)의 기본 파이프라인을 구축함.

**기본 파이프라인:** `PlanRestController` -> `PlanFacade` -> `AIService` -> AI Server

### 1.1. 파일 구조 리팩토링

-   **`AIService.java` 위치 변경**:
    -   `recommend_domain` 패키지에서 `domain/plan/service`로 이동하여 `plan` 도메인의 역할과 책임을 명확히 함.
-   **`AppConfig.java` 정리**:
    -   `common/config/AppConfig.java`에 `RestTemplate` 빈이 이미 존재함을 확인하고, 중복 생성했던 설정 파일을 정리함.

### 1.2. 주요 파일 변경 내용 (오전)

-   **`domain/plan/service/AIService.java`**: AI 서버와 직접 통신하는 서비스 로직을 구현함.
-   **`domain/plan/request/PlanResponse.java`**: AI 요약 응답을 위한 `Summary` DTO를 추가함.
-   **`domain/plan/controller/PlanRestController.java`**: API 엔드포인트를 추가함.
-   **`domain/plan/facade/PlanFacade.java`**: `AIService`를 호출하여 요약 정보를 가져오는 비즈니스 로직을 구현함.

## 2. 오후: 폴링(Polling) 방식으로 AI 결과 수신 로직 고도화

오전에 구현한 동기 방식 API는 AI 서버의 처리 시간이 길어질 경우 타임아웃이 발생할 수 있음. 이 문제를 해결하기 위해 비동기 폴링 방식으로 아키텍처를 개선함.

**개선된 아키텍처:**

1.  **최초 요청 (Client -> Server)**: `GET /api/plans/{planId}/summary` 호출
2.  **비동기 처리 (Server)**:
    -   **최초 요청 시:** 요약 생성 작업을 비동기로 시작하고, 상태를 `IN_PROGRESS`로 변경 후 즉시 **HTTP 202 Accepted** 응답을 반환함.
    -   **처리 중:** 계속해서 **HTTP 202 Accepted** 응답을 반환함.
    -   **처리 완료 시:** 저장된 요약 결과를 **HTTP 200 OK** 응답으로 반환함.
3.  **폴링 (Client -> Server)**: 클라이언트는 202 응답을 받으면, 일정 시간 후 동일한 API를 다시 호출하여 결과를 확인해야 함.

### 2.1. 주요 파일 변경 내용 (오후)

-   **`domain/plan/SummaryStatus.java` (신규 생성)**
    -   AI 요약 생성 상태(`NONE`, `IN_PROGRESS`, `COMPLETED`, `FAILED`)를 관리하는 `Enum`을 추가함.

-   **`domain/plan/domain/Plan.java`**
    -   `summaryStatus` 필드를 추가하여 DB에서 요약 생성 상태를 추적할 수 있도록 함.

-   **`common/config/AppConfig.java`**
    -   `@EnableAsync` 어노테이션을 추가하여 스프링의 비동기 처리 기능을 활성화함.

-   **`domain/plan/service/AIService.java`**
    -   `@Async` 어노테이션을 사용하여 `generateAndSaveSummary` 메소드가 비동기로 동작하도록 변경함.
    -   AI 서버 통신 후, 결과(성공 또는 실패)를 `Plan` 엔티티의 `summary`와 `summaryStatus` 필드에 직접 업데이트하도록 수정함.

-   **`domain/plan/facade/PlanFacade.java`**
    -   `getPlanSummary` 메소드에 `summaryStatus`에 따른 분기 로직을 구현함.
    -   상태가 `NONE`이면 비동기 작업을 트리거하고, `IN_PROGRESS`나 `COMPLETED`에 따라 각각 `null` 또는 최종 결과를 반환하도록 수정함.

-   **`domain/plan/controller/PlanRestController.java`**
    -   `PlanFacade`의 반환 값에 따라 클라이언트에게 **HTTP 202 Accepted** 또는 **HTTP 200 OK**를 응답하도록 로직을 수정함.
    -   Swagger 문서(`@ApiResponses`)에도 202 응답 코드를 추가하여 명세화함.

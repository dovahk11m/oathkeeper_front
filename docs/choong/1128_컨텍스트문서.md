## 7. 개발 교훈 및 주의사항 (11/28 업데이트)

### 1. Null 안전성 철저히 검증

- nullable 타입 사용 시 항상 `??` 연산자로 기본값 제공
- `throw Exception(message ?? '기본 오류 메시지')` 패턴 사용
- IDE의 null safety 경고를 무시하지 말고 즉시 수정

### 2. API 문서 정확성 확인

- 공식 문서나 IDE 자동완성으로 API 존재 여부 확인 후 사용
- 새로운 API 사용 전 반드시 공식 문서 참조 및 간단한 테스트 코드 작성
- **주의**: `Color.withValues()`는 존재하지 않음 → `withOpacity()` 또는 `withAlpha()` 사용

### 3. 비동기 패턴 신중하게 선택

- **폴링 구현 시**: `Timer.periodic` vs 재귀적 `Future.delayed` 패턴 중 적절한 것 선택
- **네트워크 요청**: 완료 시간이 불확실한 작업은 재귀적 패턴 사용 (race condition 방지)
- 동시성 이슈 가능성을 항상 고려

### 4. State 필드 가변성 주의

- `StatefulWidget`의 `State` 클래스 내에서 `setState`로 값이 변경되는 필드는 `final`로 선언하지 않음
- 컴파일러가 `setter not defined` 에러를 뱉을 때 가장 먼저 `final` 여부 확인

### 5. 서버 스펙 동기화 필수

- 클라이언트 구현 전 반드시 최신 서버 API 문서 확인
- 구 명세 사용 시 404/500 에러 발생 가능
- 불확실한 경우 `docs/choong/` 폴더 내 QnA 문서를 통해 서버팀에 확인 요청

### 6. 코드 리뷰 피드백 적극 수용

- PR 리뷰 피드백은 잠재적 버그일 수 있음
- 유사한 패턴이 다른 곳에도 있는지 프로젝트 전체 검토
- 수정 후 반드시 `flutter analyze`로 검증

### 7. 정적 분석 활용

- 코드 작성 후 `flutter analyze` 실행하여 문법 오류 및 경고 사전 식별
- Deprecated 경고를 무시하지 말고 즉시 수정

## 1. 개인 작업 계획 (충희)

### 1.1. 긴급 점검: 약속 중간 저장 문제 해결

-   **목표:** `Plan`, `Participant` 등 도메인 변경으로 인해 발생한 약속 중간 저장 문제를 해결한다.
-   **세부 과업:**
    -   **서버 측 점검:** 최근 `Plan`, `Participant` 엔티티 변경 사항(필드 추가/수정, `MovementStatus` 도입 등)이 약속 저장 로직에 영향을 주었는지 확인.
    -   **클라이언트 측 점검:** 클라이언트에서 약속 생성 및 수정 시 전송하는 데이터 구조(`DTO`)가 서버의 변경된 엔티티 구조와 일치하는지 확인.
    -   필요시 `PlanService`, `PlanFacade` 등의 약속 저장/수정 관련 로직 디버깅 및 수정.

### 1.2. AI 요약 보고서 기능 안정화 및 테스트

-   **목표:** AI 서버와의 연동 안정성을 확보하고, 실제 AI 분석 결과를 확인한다.
-   **세부 과업:**
    -   AI 서버와의 통신에서 발생할 수 있는 엣지 케이스(네트워크 오류, AI 서버 응답 지연 등)를 처리하는 로직(재시도, 타임아웃 설정 등)을 `AIService`에 추가하여 안정성 확보.
    -   AI 서버 응답이 실패했을 경우, `SummaryStatus.FAILED`로 정확히 업데이트되는지 확인 및 테스트.
    -   **실제 AI 분석 결과 확인:** 노트북을 가져온 후, AI 서버를 실행하여 실제 약속 데이터에 대한 AI 요약 분석이 정상적으로 동작하고 결과가 저장되는지 확인.

### 1.3. 실시간 지도 기능 클라이언트 연동 지원 및 테스트

-   **목표:** 클라이언트 개발자와의 협업을 통해 실시간 지도 기능의 클라이언트 연동을 완료하고, 통합 테스트 환경을 구축한다.
-   **세부 과업:**
    -   `LIVE_MAP_API.md` 문서를 기반으로 **클라이언트 개발자**와 실시간 위치 전송 및 WebSocket 구독 기능 구현에 대한 기술 지원 및 질의응답 진행.
    -   **`PlanTestApiController`에 테스트용 강제 이벤트 API 구현:**
        -   특정 참가자의 "도착" 이벤트를 강제로 트리거하는 API (`/api/plans/{planId}/participants/{participantId}/test/force-arrived`) 구현.
        -   특정 참가자의 "정체" 이벤트를 강제로 트리거하는 API (`/api/plans/{planId}/participants/{participantId}/test/force-stationary`) 구현.
        -   이를 통해 클라이언트 개발 및 테스트 편의성을 증대.
    -   **실시간 지도 앱 테스트 시나리오 및 더미 데이터 설계:**
        -   `DataInitializer12_Plan.java`에 추가된 '진행중인 약속', '대기중인 약속' 시나리오를 활용하여 실제 앱에서 실시간 위치 추적 및 이벤트(정체, 도착) 알림이 정상적으로 동작하는지 테스트 계획 수립.
        -   필요시 추가적인 더미 데이터 시나리오(예: 위치 공유 비동의 참가자, 약속 취소/완료된 약속 등)를 `DataInitializer`에 추가하여 다양한 케이스 테스트.
    -   두 명 이상의 사용자가 참여하는 시나리오로 실시간 지도 기능의 통합 테스트를 주도하고, 발생 가능한 문제점(네트워크 불안정, 백그라운드 전환 등) 디버깅 지원.

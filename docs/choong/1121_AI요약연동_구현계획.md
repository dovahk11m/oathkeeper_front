# 구현 계획 - AI 요약 폴링 연동

## 목표 설명
Flutter 앱에서 AI 요약 기능을 위한 클라이언트 측 폴링(Polling) 로직을 구현합니다. 서버는 요약 생성 중일 때 `202 Accepted`를 반환하고, 완료되면 `200 OK`를 반환하는 비동기 패턴을 사용합니다.

## 사용자 검토 필요 사항
> [!IMPORTANT]
> 이 변경 사항은 폴링 메커니즘을 도입합니다. 폴링 간격(현재 3초로 설정 예정)과 타임아웃/최대 재시도 횟수가 서버 부하에 적절한지 확인이 필요합니다.

## 변경 제안

### 도메인 계층 (Domain Layer)

#### [수정] [plan_state.dart](file:///c:/workspace_flutter/oathkeeper_front/lib/domain/plans/plan_state.dart)
- `PlanState`에 `isSummaryLoading`(로딩 중), `summaryStatus`(상태), `summary`(결과 데이터) 필드를 추가합니다.

#### [수정] [plan_repository.dart](file:///c:/workspace_flutter/oathkeeper_front/lib/domain/plans/plan_repository.dart)
- `Future<Response>`를 반환하는 `getPlanSummary(int planId)` 메소드를 추가합니다.

#### [수정] [plan_provider.dart](file:///c:/workspace_flutter/oathkeeper_front/lib/domain/plans/plan_provider.dart)
- `Timer`를 사용하여 폴링을 수행하는 `pollPlanSummary(int planId)`를 구현합니다.
- 리소스 정리를 위한 `cancelSummaryPolling()`을 구현합니다.
- [추가] 최대 재시도 횟수(10회)를 설정하여 무한 폴링을 방지합니다.

## 검증 계획

### 자동화 테스트
- `flutter test`를 실행하여 기존 로직에 회귀(regression)가 없는지 확인합니다.
- (선택 사항) 가능하다면 `fake_async` 등을 사용하여 `PlanNotifier`의 폴링 로직에 대한 유닛 테스트를 추가합니다.

### 수동 검증
1. 에뮬레이터에서 앱을 실행합니다 (`flutter run`).
2. 약속(Plan) 상세 페이지로 이동합니다.
3. 요약 생성을 트리거합니다 (UI가 연결된 경우, 그렇지 않으면 로그 확인).
4. 로그에서 `202` 응답이 반복되다가 `200` 응답이 오는지 확인합니다.
5. 상태가 올바르게 업데이트되는지 확인합니다 (`IN_PROGRESS` -> `COMPLETED`).

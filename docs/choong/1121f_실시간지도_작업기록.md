# 1121f: 실시간 지도 기능 보강 작업 기록

## 1. 개요

`1121e_실시간지도기능보강계획.md`에 따라 실시간 지도 기능의 사용자 경험을 향상시키고 기획 의도를 충족시키기 위한 고급 기능들을 구현함.

## 2. 구현 내용

### 2.1. 인메모리 맵 설정 및 `TrackService`에 연동 (Redis 대체)

-   **목표:** 실시간 위치 데이터의 빠른 접근 및 캐싱 기반 마련 (Redis 없이).
-   **수정 파일:**
    -   `src/main/resources/application-local.yml`: Redis 설정 제거.
    -   `com.oath.domain.locationevents.service.TrackService.java`: `RedisTemplate` 대신 `ConcurrentHashMap` 주입.
-   **구현 내용:**
    -   `TrackService`에 `RedisTemplate` 의존성 제거 및 `ConcurrentHashMap`을 사용하여 `realtimeLocationCache`와 `stationaryCheckCache` 정의.
    -   Redis 관련 모든 호출을 `ConcurrentHashMap` 관련 메서드(put, getOrDefault, remove)로 대체.
    -   `src/main/resources/application-local.yml`에서 Redis 설정 주석 처리.

### 2.2. 약속 페이즈 연동 로직 구현

-   **목표:** 약속 상태에 따른 위치 추적 기능의 활성화/비활성화 제어.
-   **수정 파일:**
    -   `com.oath.domain.locationevents.service.TrackService.java`
-   **구현 내용:**
    -   `TrackService`에 `PlanJpaRepository` 주입.
    -   `storeTracks` 메서드 내에서 `participant.getPlan().getStatus()`를 조회하여 약속 상태가 `COMPLETED` 또는 `CANCELED`인 경우 위치 추적 로직을 수행하지 않도록 조건부 처리. (기본적으로 `PLANNING`, `CONFIRMED`, `IN_PROGRESS` 상태에서만 고급 로직 수행 가정)

### 2.3. GPS 미변화 감지 기능 구현

-   **목표:** 사용자의 GPS 미변화 상황을 감지하고 알림 제공.
-   **신규 파일:**
    -   `com.oath.domain.locationevents.event.GpsStationaryEvent.java`: `planId`, `participantId`, `memberId`, `username`, `lastKnownLocation`, `stationaryStartTime`, `stationaryDurationMinutes`를 포함하는 이벤트 클래스 정의.
    -   `com.oath.domain.locationevents.event.listener.GpsStationaryListener.java`: `GpsStationaryEvent`를 수신하여 `AlarmFactory`를 통해 사용자에게 알림 발송.
-   **수정 파일:**
    -   `src/main/resources/application-local.yml`: `notification.policy.on-gps-stationary: EMAIL` 정책 추가.
    -   `com.oath.domain.locationevents.service.TrackService.java`: `detectGpsStationary` 메서드 추가 및 `storeTracks`에서 호출.
-   **구현 내용:**
    -   `TrackService` 내에 `STATIONARY_THRESHOLD_METERS` (10미터), `STATIONARY_DURATION_MINUTES` (5분) 상수 정의.
    -   `detectGpsStationary` 메서드에서 인메모리 맵에 `stationary:check:{participantId}` 키로 이전 위치 및 정체 시작 시간 저장.
    -   현재 위치와 이전 위치를 비교하여 `STATIONARY_THRESHOLD_METERS` 이내이고 `STATIONARY_DURATION_MINUTES` 이상 지속되면 `GpsStationaryEvent` 발행.
    -   `GpsStationaryListener`는 이벤트를 받아 `MemberRepository`를 통해 사용자 이메일을 조회하고, `AlarmFactory`를 통해 이메일 알림 발송.

### 2.4. 자동 도착 처리 기능 구현

-   **목표:** 약속 장소 근처 도달 시 자동 도착 처리 및 후속 작업 트리거.
-   **신규 파일:**
    -   `com.oath.domain.locationevents.event.ParticipantArrivedEvent.java`: `planId`, `participantId`, `memberId`, `username`, `arrivalLocation`, `arrivalTime`를 포함하는 이벤트 클래스 정의.
    -   `com.oath.domain.locationevents.event.listener.ParticipantArrivedListener.java`: `ParticipantArrivedEvent`를 수신하여 `PlanService`를 통해 참가자의 도착 상태 업데이트.
-   **수정 파일:**
    -   `com.oath.domain.locationevents.service.TrackService.java`: `detectArrival` 메서드 추가 및 `storeTracks`에서 호출.
    -   `com.oath.domain.plan.service.PlanService.java`: `updateParticipantArrivalStatus` 메서드 추가.
-   **구현 내용:**
    -   `TrackService` 내에 `ARRIVAL_RADIUS_METERS` (100미터) 상수 정의.
    -   `detectArrival` 메서드에서 약속 상태가 `IN_PROGRESS`이고, 이미 도착하지 않은 참가자에 대해 약속 장소와 현재 위치 간 거리를 계산.
    -   거리가 `ARRIVAL_RADIUS_METERS` 이내이면 `ParticipantArrivedEvent` 발행.
    -   `ParticipantArrivedListener`는 이벤트를 받아 `PlanService.updateParticipantArrivalStatus`를 호출하여 참가자의 `ParticipantStatus`를 `ARRIVED`로 변경하고, 도착 시간 및 지각 여부 계산, 관련 이벤트 발행, 약속 자동 완료 체크 로직 수행.

### 2.5. 이동 상태(MovementStatus) 도입 및 연동

-   **목표:** 약속 참여 의사결정 상태와 별개로, 참가자의 실시간 이동 상태를 명확히 관리.
-   **신규 파일:** `com.oath.domain.plan.MovementStatus.java`
-   **수정 파일:**
    -   `com.oath.domain.plan.domain.Participant.java`
    -   `com.oath.domain.plan.service.PlanService.java`
    -   `com.oath.domain.locationevents.service.TrackService.java`
-   **구현 내용:**
    -   **`MovementStatus` Enum 정의**: `HOME`, `DEPARTED`, `MOVING`, `STATIONARY`, `ARRIVED` 상태 정의.
    -   **`Participant` 엔티티 수정**:
        -   `movementStatus` 필드 추가 (`@Builder.Default(MovementStatus.HOME)`).
        -   `participantStatus` 필드에 `@Builder.Default(ParticipantStatus.PENDING)` 추가하여 견고성 강화.
        -   `markDeparted()`, `markArrived()`, `setParticipantStatus()` 메서드 내에서 `movementStatus`를 적절히 업데이트하도록 로직 추가.
    -   **`PlanService` 수정**: `recordDeparture` 및 `updateParticipantArrivalStatus` 메서드에서 `Participant` 엔티티의 메서드를 통해 `movementStatus`가 업데이트되도록 연동.
    -   **`TrackService` 수정**:
        -   `storeTracks` 메서드 내에서 위치 수신 시 `movementStatus`를 `MOVING`으로 업데이트 (도착 상태가 아닌 경우).
        -   `detectGpsStationary` 메서드 내에서 정체 감지 시 `movementStatus`를 `STATIONARY`로, 움직임 감지 시 `MOVING`으로 업데이트.
        -   `detectArrival` 메서드에서 도착 감지 시 `movementStatus`를 `ARRIVED`로 업데이트.

### 2.6. 트랜잭션 규칙 준수 및 리스너 WebSocket 알림 구현

-   **목표:** 서비스 트랜잭션 규칙을 준수하고, 클라이언트 요청에 따라 이벤트 알림을 WebSocket으로 전송.
-   **신규 파일:**
    -   `com.oath.domain.locationevents.dto.GpsStationaryNotificationDto.java`
    -   `com.oath.domain.locationevents.dto.ParticipantArrivedNotificationDto.java`
-   **수정 파일:**
    -   `com.oath.domain.plan.service.PlanService.java`
    -   `com.oath.domain.locationevents.event.listener.GpsStationaryListener.java`
    -   `com.oath.domain.locationevents.event.listener.ParticipantArrivedListener.java`
-   **구현 내용:**
    -   **`PlanService.java`**: 클래스 레벨에 `@Transactional("h2TransactionManager")`를 추가하고, 메서드 레벨의 `@Transactional`을 최적화하여 트랜잭션 관리자 명시 규칙 준수.
    -   **`GpsStationaryNotificationDto` 및 `ParticipantArrivedNotificationDto` 정의**: 클라이언트가 WebSocket 메시지를 수신했을 때 파싱할 수 있는 형태로 이벤트 정보를 담는 DTO 정의.
    -   **`GpsStationaryListener.java` 및 `ParticipantArrivedListener.java`**:
        -   `@Transactional("h2TransactionManager", propagation = Propagation.REQUIRES_NEW)`를 적용하여 트랜잭션 관리자 명시 규칙 준수.
        -   `SimpMessagingTemplate`을 주입받아 클라이언트가 선호하는 `/topic/plans/{planId}/events` 토픽으로 해당 Notification DTO를 WebSocket 메시지로 전송하는 로직 추가.

### 2.7. 컴파일 오류 수정 및 `Status` Enum 보강

-   **목표:** 발생한 컴파일 오류를 해결하고, `Status` Enum에 필요한 상태 추가.
-   **수정 파일:**
    -   `com.oath.domain.plan.Status.java`
    -   `com.oath.domain.locationevents.event.listener.ParticipantArrivedListener.java`
    -   `com.oath.domain.locationevents.event.listener.GpsStationaryListener.java`
    -   `com.oath.domain.plan.service.PlanService.java`
-   **구현 내용:**
    -   **`Status.java`**: `IN_PROGRESS`와 `CANCELED` 상태를 추가하여 `TrackService`에서 약속 상태를 올바르게 참조할 수 있도록 함.
    -   **`ParticipantArrivedListener.java` 및 `GpsStationaryListener.java`**: `@Transactional` 어노테이션의 `value` 속성 누락으로 인한 컴파일 오류 (`java: annotation values must be of the form 'name=value'`)를 `value = "h2TransactionManager"`로 명시하여 해결.
    -   **`PlanService.java`**: `updateParticipantArrivalStatus` 메서드의 두 번째 인자 타입을 `ParticipantStatus`에서 `MovementStatus`로 변경하고, 메서드 내부에서 `participant.setMovementStatus(movementStatus)`를 호출하도록 수정하여 `ParticipantArrivedListener`와의 타입 불일치 오류 해결.

## 3. 클라이언트(Flutter) 개발팀 요청 사항에 대한 현재 상태

### 3.1. 약속 상태(Phase) 동기화 API
-   **상태:** `PlanRestController`의 `GET /api/plans/{id}` API를 통해 `PlanResponse.CreatePlan` DTO를 받으면 `status` 필드를 통해 약속의 현재 상태를 알 수 있음. 클라이언트는 이 API를 호출하여 약속 상태를 동기화할 수 있음.

### 3.2. 이벤트 수신 채널 일원화 또는 분리 명세
-   **상태:** `GpsStationaryEvent`와 `ParticipantArrivedEvent`는 이제 클라이언트가 선호하는 별도 채널 (`/topic/plans/{planId}/events`)로 WebSocket을 통해 전송됨.

### 3.3. 도착 판정 기준 공유
-   **상태:** 서버에서 도착으로 판정하는 반경은 `ARRIVAL_RADIUS_METERS` 상수로 **100미터**로 설정됨.
-   **서버 동작:** 서버에서 도착 판정 시 `ParticipantArrivedEvent`가 발행되고, `PlanService.updateParticipantArrivalStatus`를 호출하여 참가자의 `ParticipantStatus`를 `ARRIVED`로 변경함. 즉, 서버에서 `status`가 변경됨. 클라이언트는 이 변경된 상태를 `getPlan` API를 통해 주기적으로 조회하거나, 별도의 WebSocket 알림을 통해 수신할 수 있음.

### 3.4. 테스트용 강제 이벤트 트리거 API
-   **상태:** 현재 구현되어 있지 않음. 필요하다면 `PlanTestApiController`와 같은 테스트용 컨트롤러에 추가 가능.

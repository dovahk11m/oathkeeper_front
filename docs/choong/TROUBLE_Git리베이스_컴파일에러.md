# Git Rebase 이후 발생한 컴파일 에러 및 기능 오류 트러블슈팅

- **작성일:** 2025-11-18

> `git rebase` 과정에서 컨플릭트를 해결하다가 발생한 연쇄적인 오류와 그 해결 과정을 기록합니다.

## 1. 문제 상황

`git rebase`로 최신 브랜치를 반영하고 컨플릭트를 해결한 직후, 다음과 같은 두 가지 문제가 동시에 발생했습니다.

1.  **컴파일 에러 발생**: 앱이 빌드조차 되지 않고, 다수의 파일에서 `uri_does_not_exist` 에러가 발생했습니다.
2.  **특정 기능의 صامت한 오류(Silent Error)**: 컴파일 에러를 해결한 후에도, ‘분석 리포트’ 페이지에 진입 시 아무런 내용도 표시되지 않는 현상이 나타났습니다.

## 2. 원인 분석 및 해결 과정

### 2.1. 원인 1: 컴파일 에러 (URI doesn't exist)

- **에러 로그**
  ```
  error: Target of URI doesn't exist: 'package:oath_client/common/http_util.dart'. (uri_does_not_exist)
  ```

- **분석**: Rebase로 병합된 최신 코드에서 `http_util.dart` 파일이 `lib/common/`에서 `lib/common/utils/` 폴더로 이동되었습니다. 하지만 컨플릭트 해결 과정에서 일부 파일(`review_repository.dart`, `live_map_page.dart`)이 이 변경사항을 반영하지 못하고, 여전히 예전 경로를 `import` 하고 있었기 때문에 발생한 문제였습니다.

- **해결**: 
  1. `grep` 명령어로 예전 경로(`package:oath_client/common/http_util.dart`)를 참조하는 모든 파일을 찾아냈습니다.
  2. 해당 파일들의 `import` 구문을 올바른 새 경로(`package:oath_client/common/utils/http_util.dart`)로 수정하여 컴파일 에러를 해결했습니다.

### 2.2. 원인 2: 기능 오류 (요약 페이지 데이터 누락)

- **증상**: 컴파일 에러 해결 후 앱은 실행되었으나, ‘분석 리포트’ 페이지에서 서버로부터 데이터를 성공적으로 받아왔음에도 화면에 아무것도 표시되지 않았습니다.

- **분석**: `rebase` 컨플릭트 해결 과정에서, `metrics_repository.dart` 파일이 최신 API 응답 형식을 처리하는 로직이 없는 **과거 버전으로 덮어씌워진 것**을 확인했습니다. 
  - **서버 응답**: `{"success":true, "data":"요약 텍스트..."}` (data 필드에 문자열)
  - **잘못된 코드**: 과거 버전의 파싱 로직은 위와 같은 형식을 해석하지 못하고, 빈 문자열(`''`)을 반환하여 화면에 아무것도 보이지 않는 ‘صامت한 오류’를 유발했습니다.

- **해결**: 
  1. `metrics_repository.dart` 파일의 데이터 파싱 함수(`_extractText`)를 열었습니다.
  2. 서버가 보내주는 `{"data": "..."}` JSON 구조를 올바르게 해석하여 문자열을 추출하는 로직을 다시 추가했습니다. 이로써 데이터 파싱이 정상적으로 이루어져 요약 내용이 화면에 표시되었습니다.

## 3. 결론 및 교훈

`git rebase`는 브랜치 히스토리를 깔끔하게 관리할 수 있는 강력한 도구이지만, 컨플릭트 해결 시 파일의 내용뿐만 아니라 **파일의 이동이나 구조 변경**까지 세심하게 확인해야 함을 알게 되었습니다.

특히, 한 파일의 변경이 의존성을 가진 다른 여러 파일에 연쇄적인 컴파일 에러를 유발할 수 있으며, 심지어 컨플릭트 해결 과정에서 과거 코드로 덮어씌워져 기능이 조용히 실패하는 ‘회귀 버그(Regression Bug)’가 발생할 수 있음을 인지하게 되었습니다.

향후 유사한 문제 발생 시, 다음 순서로 점검하는 것이 효율적입니다.

1.  **컴파일 에러 메시지 확인**: 에러가 발생한 파일과 원인을 가장 먼저 파악한다.
2.  **Git 변경 내역 확인 (`git diff`)**: Rebase로 인해 어떤 파일들이 어떻게 변경되었는지 전체적으로 파악하여 숨겨진 원인을 찾는다.
3.  **Local History 활용**: IDE의 ‘Local History’ 기능을 활용하여 Rebase 이전의 정상 작동 코드를 참고하거나 복원한다.

## 📋 요구사항

### 배경

- GROUP_API.md에 새로운 API 추가: `GET /api/groups/{groupId}/plans?status=COMPLETED`
- 하나의 그룹에 여러 약속이 누적될 수 있음
- 사용자가 과거 약속 중 원하는 것을 선택하여 요약을 볼 수 있어야 함

### UI 구조

```
┌─────────────────────────────────────┐
│   약속 요약                          │
├─────────────────────────────────────┤
│  [상세보기]  [목록보기]              │ ← 탭
├─────────────────────────────────────┤
│                                     │
│  [상세보기 탭]                       │
│  - 선택된 약속의 AI 요약 표시        │
│  - 로딩/완료/실패 상태               │
│                                     │
│  [목록보기 탭]                       │
│  - 완료된 약속 목록 (COMPLETED)      │
│  - 각 항목: 제목, 날짜/시간          │
│  - 클릭 시 → 상세보기 탭으로 전환    │
│    + 해당 약속 요약 로딩 시작        │
│                                     │
└─────────────────────────────────────┘
```

### 동작 플로우

1. **시트 열림** → 기본적으로 "상세보기" 탭 (현재 planId의 요약 표시)
2. **"목록보기" 탭 클릭** → 완료된 약속 목록 표시
3. **목록에서 약속 클릭** → "상세보기" 탭으로 자동 전환 + 해당 약속 요약 로딩

### 1. PlanSummaryResponse DTO 개선

**문제점:**

- `MetricsNotifier`에서 `response.success && response.data != null` 같은 로직을 직접 사용
- 응답 상태 판단 로직이 외부에 노출되어 있음
- 객체지향적이지 않은 설계

**개선:**

**파일:** `lib/domain/metrics/plan_summary.dart`

```dart
@freezed
class PlanSummaryResponse with _$PlanSummaryResponse {
  const PlanSummaryResponse._(); // private constructor for custom methods

  const factory PlanSummaryResponse({
    required bool success,
    PlanSummaryData? data,
    String? message,
  }) = _PlanSummaryResponse;

  factory PlanSummaryResponse.fromJson(Map<String, dynamic> json) =>
      _$PlanSummaryResponseFromJson(json);

  /// 요약 생성 완료 여부
  bool get isCompleted => success && data != null;

  /// 요약 생성 중 여부
  bool get isProcessing => success && data == null && message != null;
}
```

✅ 응답 상태 판단 로직 캡슐화

### 2. 약속 목록 상태 관리 분리

**문제점:**

- `metrics_summary_sheet.dart`에서 `_planList`, `_loadingPlanList`를 로컬 상태로 관리
- AI 요약은 `metricsProvider`로 관리하여 상태 관리 방식이 일관되지 않음
- 위젯의 책임이 과도하게 많음
- 테스트 및 확장이 어려움

**개선:**

#### 2.1. PlanListState 생성

**파일:** `lib/domain/plans/plan_list_state.dart`

```dart
import 'package:freezed_annotation/freezed_annotation.dart';
import 'simple_plan.dart';

part 'plan_list_state.freezed.dart';

/// 약속 목록 상태
@freezed
class PlanListState with _$PlanListState {
  const factory PlanListState({
    @Default([]) List<SimplePlan> plans,
    @Default(false) bool isLoading,
    String? error,
  }) = _PlanListState;
}
```

#### 2.2. PlanListNotifier 생성

**파일:** `lib/domain/plans/plan_list_provider.dart`

```dart
import 'package:flutter/foundation.dart';
import 'package:flutter_riverpod/flutter_riverpod.dart';

import '../groups/group_repository.dart';
import 'plan_list_state.dart';

/// 약속 목록 Notifier
class PlanListNotifier extends Notifier<PlanListState> {
  @override
  PlanListState build() {
    return const PlanListState();
  }

  /// 완료된 약속 목록 조회
  Future<void> fetchCompletedPlans(int groupId) async {
    if (groupId <= 0) return;

    state = state.copyWith(isLoading: true, error: null);

    try {
      final groupRepo = ref.read(groupRepositoryProvider);
      final response = await groupRepo.fetchCompletedPlans(groupId);

      debugPrint('[PlanListNotifier] 약속 목록 조회 성공: ${response.items.length}개');

      state = state.copyWith(
        plans: response.items,
        isLoading: false,
      );
    } catch (e) {
      debugPrint('[PlanListNotifier] 약속 목록 조회 실패: $e');
      state = state.copyWith(
        isLoading: false,
        error: '약속 목록 조회 실패: $e',
      );
    }
  }

  /// 상태 초기화
  void reset() {
    debugPrint('[PlanListNotifier] 상태 초기화');
    state = const PlanListState();
  }
}

/// 약속 목록 Provider
final planListProvider =
    NotifierProvider<PlanListNotifier, PlanListState>(PlanListNotifier.new);
```

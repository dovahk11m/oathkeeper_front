### 서버 API 변경사항

#### 1. Spring 서버 API (METRIC_API.md)

- **엔드포인트:** `GET /api/plans/{planId}/summary`
- **폴링 방식:** 클라이언트가 2~3초 간격으로 주기적 호출
- **응답 상태:**
  - `data: null` + message → 생성 중 (계속 폴링)
  - `data: { id, title, summary }` → 완료 (폴링 중단)
  - `500 에러` → 실패 (폴링 중단)

#### 2. Python AI 서버 API (1124aAI서버명세.md)

- **메트릭 저장:** `POST /metrics/analyze` (Spring → Python)
- **요약 생성:** `GET /metrics/report/{planId}`
- **규칙 기반 요약:** `GET /metrics/report/{planId}/text`
- **LLM 요약:** `POST /metrics/report/{planId}/text`
- **에러 코드:**
  - `404` → plan 폴더 없음
  - `409` → 메트릭 데이터 부족

### 1. Domain Layer 수정

#### 1.1. DTO 모델 추가/수정

**파일:** `lib/domain/metrics/models/plan_summary.dart` (신규)

```dart
/// Spring API 응답 DTO
class PlanSummaryResponse {
  final bool success;
  final PlanSummaryData? data;
  final String? message;

  PlanSummaryResponse({
    required this.success,
    this.data,
    this.message,
  });

  factory PlanSummaryResponse.fromJson(Map<String, dynamic> json) {
    return PlanSummaryResponse(
      success: json['success'] ?? false,
      data: json['data'] != null
          ? PlanSummaryData.fromJson(json['data'])
          : null,
      message: json['message'],
    );
  }

  /// 생성 중 상태 확인
  bool get isProcessing => success && data == null && message != null;

  /// 완료 상태 확인
  bool get isCompleted => success && data != null;
}

class PlanSummaryData {
  final int id;
  final String title;
  final String summary;

  PlanSummaryData({
    required this.id,
    required this.title,
    required this.summary,
  });

  factory PlanSummaryData.fromJson(Map<String, dynamic> json) {
    return PlanSummaryData(
      id: json['id'],
      title: json['title'],
      summary: json['summary'],
    );
  }
}
```

**작업 내용:**

- Spring API 응답 구조에 맞는 DTO 생성
- 상태 확인 헬퍼 메서드 추가 (`isProcessing`, `isCompleted`)

```dart
class MetricsRepository {
```

### 2. State Management 수정

#### 2.1. PlanProvider/PlanState 확인 및 수정

**파일:** `lib/domain/plans/plan_provider.dart`, `lib/domain/plans/plan_state.dart`

**현재 상태:**

- `metrics_summary_sheet.dart`에서 `ref.read(planProvider.notifier).pollPlanSummary(planId)` 호출
- PlanState에 `isSummaryLoading`, `summaryStatus`, `summary` 필드 존재

**필요 작업:**

1. PlanState 필드 확인:

   ```dart
   class PlanState {
     // ...
     final bool isSummaryLoading;
     final String? summaryStatus; // 'PROCESSING', 'COMPLETED', 'FAILED'
     final Map<String, dynamic>? summary;
     final String? error;
   }
   ```

2. PlanNotifier 폴링 로직 확인:
   ```dart
   class PlanNotifier extends StateNotifier<PlanState> {
     Timer? _pollingTimer;

     Future<void> pollPlanSummary(int planId) async {
       // 기존 폴링 취소
       cancelSummaryPolling();

       // 로딩 상태로 전환
       state = state.copyWith(
         isSummaryLoading: true,
         summaryStatus: 'PROCESSING',
       );

       // 폴링 시작 (2~3초 간격)
       _pollingTimer = Timer.periodic(Duration(seconds: 3), (_) async {
         try {
           final repo = ref.read(metricsRepositoryProvider);
           final response = await repo.fetchPlanSummary(planId);

           if (response.isCompleted) {
             // 완료 → 폴링 중단
             cancelSummaryPolling();
             state = state.copyWith(
               isSummaryLoading: false,
               summaryStatus: 'COMPLETED',
               summary: {
                 'id': response.data!.id,
                 'title': response.data!.title,
                 'summary': response.data!.summary,
               },
             );
           } else if (response.isProcessing) {
             // 계속 대기
             print('[PlanNotifier] AI 요약 생성 중...');
           }
         } catch (e) {
           // 에러 → 폴링 중단
           cancelSummaryPolling();
           state = state.copyWith(
             isSummaryLoading: false,
             summaryStatus: 'FAILED',
             error: e.toString(),
           );
         }
       });
     }

     void cancelSummaryPolling() {
       _pollingTimer?.cancel();
       _pollingTimer = null;
     }
   }
   ```

**작업 내용:**

- PlanState에 필요한 필드가 있는지 확인
- 없으면 추가 (isSummaryLoading, summaryStatus, summary, error)
- 폴링 로직 구현 또는 수정
- 폴링 간격: 2~3초 (METRIC_API.md 명세 준수)

   ```dart
   class _MetricsSummarySheetState extends ConsumerState<MetricsSummarySheet> {
     @override
     void initState() {
       super.initState();
       WidgetsBinding.instance.addPostFrameCallback((_) {
         if (widget.planId > 0) {
           // 폴링 시작
           ref.read(planProvider.notifier).pollPlanSummary(widget.planId);
         }
       });
     }

     @override
     void dispose() {
       // 폴링 중단
       ref.read(planProvider.notifier).cancelSummaryPolling();
       super.dispose();
     }
   }
   ```

### 4. 에러 처리 개선

#### 4.1. 404/409 에러 처리

**Python AI 서버 에러 규칙:**

- `404` → plan 폴더 없음 (활성 약속 없음)
- `409` → 메트릭 데이터 부족 (집계 전)

**Spring API 에러 처리:**

- Spring이 Python 에러를 그대로 전달하는지 확인 필요
- 클라이언트에서 404/409 처리 로직 추가

**MetricsSummarySheet 수정:**

```dart
Future<void> _startPolling() async {
  try {
    ref.read(planProvider.notifier).pollPlanSummary(widget.planId);
  } on DioException catch (e) {
    final statusCode = e.response?.statusCode;
    if (statusCode == 404) {
      setState(() => _noActivePlan = true);
    } else if (statusCode == 409) {
      setState(() => _notReadyYet = true);
    } else {
      _toast('요약 생성 실패');
    }
  }
}
```

**작업 내용:**

- PlanNotifier에서 404/409 에러를 별도 상태로 관리
- UI에서 에러 코드별 안내 메시지 표시

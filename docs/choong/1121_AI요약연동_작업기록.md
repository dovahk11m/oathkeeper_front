# 1121 AI 요약 기능 클라이언트 연동 작업

## 0. 상황 설명

기존에는 AI 요약 요청 시 서버가 바로 응답을 줬는데, AI 모델이 무거워지면서 응답 시간이 길어짐. 그래서 서버 로직이 비동기 처리(`202 Accepted`)로 바뀌었고, 클라이언트는 폴링(Polling) 방식으로 결과를 확인해야 하는 상황임. 이에 맞춰 클라이언트 쪽 코드를 수정해야 함.

## 1. 작업 목표

서버의 AI 요약 API가 비동기 폴링 방식으로 변경됨에 따라, 클라이언트의 `plan` 도메인 관련 코드를 수정하여 이를 지원함.

- **API**: `GET /api/plans/{planId}/summary`
- **로직**:
    1. 최초 요청 시 서버는 `202 Accepted`를 반환하며 AI 요약 생성을 시작함.
    2. 클라이언트는 `202` 응답을 받으면, 주기적으로 동일한 API를 다시 호출(폴링)함.
    3. 요약 생성이 완료되면 서버는 `200 OK`와 함께 요약 데이터를 반환하고, 클라이언트는 폴링을 중단함.

## 2. 작업 순서

### 2.1. [1단계] 도메인 레이어 (`lib/domain/plans`)

데이터 관리 및 비즈니스 로직을 담당하는 도메인 레이어를 먼저 작업함.

#### 1) `plan_state.dart` 수정
AI 요약의 폴링 상태와 결과를 관리하기 위해 `PlanState`에 새로운 필드를 추가함.

- `isSummaryLoading` (bool): 폴링이 진행 중인지 여부.
- `summaryStatus` (String?): 요약의 현재 상태 (`NONE`, `IN_PROGRESS`, `COMPLETED`, `FAILED`).
- `summary` (Map<String, dynamic>?): 성공 시 수신된 요약 데이터.

```dart
@freezed
class PlanState with _$PlanState {
  const factory PlanState({
    // ... 기존 필드
    @Default(false) bool isSummaryLoading,
    String? summaryStatus,
    Map<String, dynamic>? summary,
  }) = _PlanState;
}
```

#### 2) `plan_repository.dart` 수정
`PlanRepository`에 AI 요약 API를 호출하는 `getPlanSummary` 메소드를 추가함.
서버의 상태 코드(200, 202)를 구분해야 하므로 `Response` 객체를 반환하거나, 상태 코드를 포함한 커스텀 DTO를 반환하도록 구현함.

```dart
Future<Response> getPlanSummary(int planId) async {
  // GET /plans/$planId/summary
}
```

#### 3) `plan_provider.dart` 수정
`PlanNotifier`에 AI 요약 폴링을 처리하는 핵심 로직을 구현함.

- **`pollPlanSummary(int planId)`**:
    - `getPlanSummary` 호출.
    - `202` 응답 시: `Timer`를 사용해 3초 간격으로 재요청 (최대 횟수 제한 고려).
    - `200` 응답 시: 타이머 중지, `summary` 데이터 저장, 상태 `COMPLETED`로 변경.
    - 에러 발생 시: 상태 `FAILED`로 변경, 폴링 중단.
- **`cancelSummaryPolling()`**:
    - 화면 이탈 시 타이머 해제.

### 2.2. [2단계] UI 레이어 연동

도메인 로직이 완성되면 실제 화면에 연동함.

- **진입 시점**: 약속 상세 화면 또는 요약 탭 진입 시 `pollPlanSummary` 호출.
- **상태별 UI**:
    - `IN_PROGRESS`: "AI가 요약 중입니다..." 로딩 표시.
    - `COMPLETED`: 요약 텍스트 및 카드 렌더링.
    - `FAILED`: "요약 생성에 실패했습니다." 메시지 및 재시도 버튼.

## 4. 작업 완료 보고서

### 작업 요약
AI 요약 기능의 안정적인 동작을 위해 서버의 비동기 응답(202 Accepted)을 처리하는 클라이언트 측 폴링 로직을 구현하고 UI에 연동했음.

### 변경 사항

#### 1. 도메인 레이어 (Domain Layer)
- **`lib/domain/plans/plan_state.dart`**
    - `isSummaryLoading`, `summaryStatus`, `summary` 필드를 추가하여 요약 상태를 관리하도록 했음.
- **`lib/domain/plans/plan_repository.dart`**
    - `getPlanSummary(int planId)` 메소드를 추가하여 AI 요약 API(`GET /plans/{planId}/summary`)를 호출하도록 했음.
- **`lib/domain/plans/plan_provider.dart`**
    - `pollPlanSummary(int planId)`: 3초 간격으로 서버를 폴링하며 상태(202 -> 200)를 체크하는 로직을 구현했음.
    - `cancelSummaryPolling()`: 화면 이탈 시 폴링을 중단하는 로직을 추가했음.

#### 2. UI 레이어 (UI Layer)
- **`lib/view/metrics/metrics_summary_sheet.dart`**
    - 기존의 직접 API 호출 방식을 `PlanNotifier`를 사용하는 방식으로 변경했음.
    - 'AI 요약' 탭 선택 시 `pollPlanSummary`가 호출되도록 연결했음.
    - `PlanState`를 구독하여 로딩, 완료, 실패 상태에 따라 적절한 UI를 표시하도록 수정했음.

### 검증 결과
- **앱 빌드 및 실행**: 에뮬레이터(Pixel 7)에서 앱이 정상적으로 빌드되고 실행됨을 확인했음.
- **기능 동작**: 'AI 요약' 탭 진입 시 폴링이 시작되고, 결과 수신 시 텍스트가 표시될 것으로 예상됨.

### 향후 참고 사항
- 폴링 간격(현재 3초)이나 최대 재시도 횟수는 서버 부하 및 사용자 경험에 따라 조정이 필요할 수 있음.

### 추가 수정 사항 (PR 리뷰 반영)
- **무한 폴링 방지**: `PlanNotifier`에 최대 재시도 횟수(10회, 약 30초) 제한을 추가하여, 서버 응답이 지연될 경우 폴링을 중단하고 실패 처리하도록 개선했음.
- **로그 포맷 수정**: `PlanRepository`에서 로그 출력 시 문자열 보간 오류를 수정하여 디버깅 편의성을 높였음.

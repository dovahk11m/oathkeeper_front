# 1126 실시간 지도 구현 계획 (클라이언트 관점)

## 0. 배경
- 서버 명세 정리: `GROUP_API.md`, `METRIC_API.md`, `LIVE_MAP_API.md`, `1126_JAVA_SERVER_REQ.md`.
- 목표: 실시간 위치 공유(업로드 + 수신), 정지/도착 이벤트 반영, 테스트용 강제 API 활용해 UX 확인.

## 1. 해야 할 일 (우선순위)
1) **위치 업로드 파이프라인 구축**
   - API: `POST /api/track/tracks/bulk` (JWT 필요)
   - 클라 작업: geolocator 권한/수집 → 3~5초 주기로 배치 전송 → 실패 시 백오프/재시도(간단히 큐잉)
   - 상태: 업로드 중 로딩 플래그, 에러 토스트 정도
2) **WebSocket 수신/연결 관리**
   - 경로: `/ws-stomp`(SockJS)/`/ws`, 구독 `/topic/plans/{planId}/live`, `/topic/plans/{planId}/events`
   - 헤더: CONNECT 시 Authorization Bearer 포함
   - 재연결: 백오프(1-2-4-8s) + 최대 횟수 설정, 구독 재등록
3) **지도/상태 렌더링**
   - 라이브 위치: 멤버별 마커 + 마지막 시각(lastLiveTs) 표시
   - 이벤트: GPS_STATIONARY, PARTICIPANT_ARRIVED 알림 배지/토스트/마커 강조
   - Plan status 연동: `status`가 진행(IN_PROGRESS)일 때만 구독/업로드 활성, 종료 시 해제
4) **테스트용 API 활용 (스모크)**
   - `POST /api/plans/{planId}/participants/{participantId}/test/force-movement-status?status=...`
   - `.../test/force-stationary`, `.../test/force-arrived`
   - 시나리오: MOVING → STATIONARY → ARRIVED 전환하며 UI/이벤트 흐름 검증
5) **그룹/플랜 메트릭스와 연계**
   - 플랜 완료 후 요약 폴링(1124/1125 구현) 정상 동작 확인
   - 그룹 요약 `GET /api/groups/{groupId}/metrics/summary` 폴링 UX 점검

## 2. 설계 결정 메모
- 위치 업로드 주기: 3~5초(배터리/정확도 균형). 배치 points 배열.
- 업로드 실패 처리: 네트워크 오류 시 로컬 큐(메모리) 보관 후 재송신. 영구 저장은 1차에서 생략.
- WebSocket 인증: STOMP CONNECT header에 JWT. 끊김 감지 시 지수 백오프.
- 이벤트 처리: `/events` 메시지 타입에 따라 UI 토스트 + 상태 배지 업데이트.
- 기존 코드 갭: `lib/view/live_map/live_map_page.dart`는 하드코딩 WS URL(`/ws`, room 토픽)·REST(`/api/location/update/recent`, 192.168.0.187)·커스텀 presence 사용 → 명세와 불일치. tracking_repo/provider도 동일. 전면 교체 필요.

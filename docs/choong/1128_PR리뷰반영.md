# 1128 PR 리뷰 피드백 반영 작업

## 작업 배경

2025-11-27 PR 리뷰에서 지적된 두 가지 이슈:

1. `group_provider.dart`: `apiResponse.message`가 null일 수 있는데 Exception 생성자에 그대로 전달
2. `live_map_page.dart`: 존재하지 않는 `Color.withValues()` 메서드 사용

## 완료된 작업

### 1. group_provider.dart - null 안전성 문제 수정

**수정 위치**: 30번, 69번, 96번 줄

**수정 내용**:

```dart
// Before
throw Exception(apiResponse.message);
state = state.copyWith(isLoading: false, error: apiResponse.message);

// After
throw Exception(apiResponse.message ?? '그룹 목록을 불러오는 중 오류가 발생했습니다.');
state = state.copyWith(isLoading: false, error: apiResponse.message ?? '그룹 생성 중 오류가 발생했습니다.');
state = state.copyWith(isLoading: false, error: apiResponse.message ?? '멤버 추가 중 오류가 발생했습니다.');
```

**효과**: `NullThrownError` 방지, 사용자에게 명확한 오류 메시지 제공

### 2. live_map_page.dart - Color API 오류 수정

**수정 위치**: 258번, 260번 줄

**수정 내용**:

```dart
// Before (컴파일 에러)
color: color.withValues(alpha: 0.1),
border: Border.all(color: color.withValues(alpha: 0.4)),

// After
color: color.withAlpha(25), // 0.1 * 255 ≈ 25
border: Border.all(color: color.withAlpha(102)), // 0.4 * 255 ≈ 102
```

**효과**: 컴파일 에러 해결, 정상적인 투명도 적용

## 참고사항

### 3. 폴링 Race Condition 수정 (추가 리뷰)

**수정 파일**: `group_metrics_provider.dart`, `metrics_provider.dart`

**문제점**:

- `Timer.periodic` 사용 시 API 응답 시간이 폴링 주기보다 길어질 경우 여러 요청이 겹쳐 race condition 발생 가능
- 예: 첫 번째 요청이 처리 중인데 두 번째 요청이 시작될 수 있음

**수정 내용**:

```dart
// Before - Timer.periodic (race condition 위험)
_pollingTimer = Timer.periodic(const Duration(seconds: 2), (_) {
  fetchGroupSummary(groupId);
});

// After - 재귀적 Future.delayed 패턴
void _startPolling(int groupId) {
  _stopPolling();
  _scheduleNextPoll(groupId);
}

void _scheduleNextPoll(int groupId) {
  _pollingTimer = Timer(const Duration(seconds: 2), () async {
    // 이전 요청이 완료된 후에만 다음 폴링 실행
    await fetchGroupSummary(groupId);

    // PENDING 상태면 다음 폴링 스케줄링 (재귀)
    if (state.summary?.status == 'PENDING') {
      _scheduleNextPoll(groupId);
    }
  });
}
```

**효과**:

- 한 번에 하나의 요청만 활성화되도록 보장
- 이전 작업이 완료된 후에만 다음 폴링 스케줄링
- 네트워크 지연 시에도 안전한 동작 보장

## 📝 앞으로 코드 작성 시 주의사항 (반성)

### 1. Null 안전성 철저히 검증

- **문제**: `apiResponse.message`가 nullable인데 null 체크 없이 Exception에 전달
- **교훈**: nullable 타입을 사용할 때는 항상 `??` 연산자로 기본값 제공
- **실천**: IDE의 null safety 경고를 무시하지 말고 즉시 수정

### 2. API 문서 정확성 확인

- **문제**: `Color.withValues()` 메서드가 존재하지 않는데 문서에 잘못 기재
- **교훈**: 공식 문서나 IDE 자동완성으로 API 존재 여부 확인 후 사용
- **실천**: 새로운 API 사용 전 반드시 공식 문서 참조 및 간단한 테스트 코드 작성

### 3. 비동기 패턴 신중하게 선택

- **문제**: `Timer.periodic` 사용으로 race condition 위험 발생
- **교훈**: 폴링 구현 시 이전 요청 완료 여부를 고려한 패턴 선택 필요
- **실천**:
  - 주기적 작업 시 `Timer.periodic` vs 재귀적 `Future.delayed` 패턴 중 적절한 것 선택
  - 네트워크 요청처럼 완료 시간이 불확실한 작업은 재귀적 패턴 사용
  - 동시성 이슈 가능성을 항상 고려

### 4. 코드 리뷰 피드백 적극 수용

- **교훈**: PR 리뷰에서 지적된 사항은 단순 스타일 이슈가 아닌 잠재적 버그일 수 있음
- **실천**:
  - 리뷰 피드백을 방어적으로 받아들이지 말고 학습 기회로 활용
  - 유사한 패턴이 다른 곳에도 있는지 프로젝트 전체 검토
  - 수정 후 반드시 `flutter analyze`로 검증

### 5. 문서화의 정확성 유지

- **문제**: 컨텍스트 문서에 잘못된 API 정보 기재
- **교훈**: 문서는 다른 개발자가 참고하므로 정확성이 매우 중요
- **실천**:
  - 문서 작성 시 실제 코드로 검증 후 기재
  - 버전별 차이가 있는 API는 버전 명시
  - 정기적으로 문서 내용과 실제 코드 일치 여부 검토
